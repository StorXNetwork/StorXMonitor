Setup CyberLs Storage Node Using the Shell Script

Use these shell scripts to bootstrap, start, stop, and upgrade a storage node for CyberLs. Have a valid XDC wallet, email, and public server IP ready. Identity creation can take a long time — leave the process running until it finishes.

Quick commands

Full flow at a glance. Step-by-step details and extra helpers are below (commands on the right).

# Clone
sudo su -c "bash <(wget -qO- https://raw.githubusercontent.com/StorXNetwork/Storage-Node/main/clone_repo.sh)" root
cd Storage-Node

# Bootstrap (installs Docker, .env, identity)
sudo bash bootstrap.sh

# After identity finishes, start / check / stop / upgrade
sudo bash start-node.sh
sudo bash check-logs.sh
sudo bash stop-node.sh
sudo bash ./upgrade.sh

Requirements

Hardware

  • 6 CPU cores
  • 8 GB RAM (16 GB recommended)
  • 1 TB+ SSD / NVMe
  • Ubuntu 20.04+ (64-bit) recommended

Network

  • Open ports 28967 (TCP/UDP) and 14002 (TCP)
  • ~10 TB bandwidth / month
  • 25+ Mbps up & down
  • 24/7 uptime

Before you start: Bootstrap asks for an XDC wallet (xdc…), email, and auto-detects public IP as IP:28967. Keep identity files under ~/.storx/identity safe — losing them means losing the node identity.

Node setup — details & commands

1. Clone the Storage-Node repo

Fetch the shell scripts on the server. Prefer the one-liner as root, or use plain git clone.

Confirm the folder exists, then enter it before any other script.

sudo su -c "bash <(wget -qO- https://raw.githubusercontent.com/StorXNetwork/Storage-Node/main/clone_repo.sh)" root
sudo su -c "bash <(wget -qO- https://raw.githubusercontent.com/StorXNetwork/Storage-Node/main/clone_repo.sh)" root
ls | grep Storage-Node
cd Storage-Node

2. Bootstrap (Docker + .env + identity)

bootstrap.sh installs Docker if needed, creates .env (wallet / email / address), prepares ~/.storx, and starts identity creation.

Identity often runs for hours. If you see “already running in the background”, wait — then re-run bootstrap after it finishes.

Optional: install Docker alone with sudo bash install_docker.sh, or create identity alone with sudo bash identity_creation.sh.

sudo bash bootstrap.sh
# Check identity still creating
ps -ef | grep ide

# Helpers (only if needed)
sudo bash install_docker.sh
sudo bash identity_creation.sh

3. Verify setup files

Before starting, confirm identity certs and .env exist. Address should look like YOUR_PUBLIC_IP:28967.

ls -la ~/.storx/identity/
cat .env
docker --version

4. Start the node

Starts the Docker container storage_node_container with ports 28967 and 14002. If a container with that name already exists, stop/remove it first (or use upgrade).

sudo bash start-node.sh
docker ps | grep storage_node_container

5. Check logs

Follow container logs to confirm the node is healthy. Press Ctrl+C to exit the log stream (node keeps running).

sudo bash check-logs.sh

6. Open the node dashboard

In a browser: http://YOUR_IP_ADDRESS:14002. Ensure firewall / security group allows inbound 14002 and 28967.

# Example firewall (ufw)
sudo ufw allow 28967/tcp
sudo ufw allow 28967/udp
sudo ufw allow 14002/tcp
sudo ufw status

7. Stop the node

Stops and removes the running container when you need to take the node offline or before a clean restart.

sudo bash stop-node.sh

8. Upgrade the node

Pulls latest scripts and upgrades the node image/config without a full re-bootstrap.

cd Storage-Node
sudo bash ./upgrade.sh

9. Connect the node in CyberLs (node group)

Do not paste node IDs. After registration / Settings → My storage nodes:

  • Create your node group (Step 1)
  • Copy the shell commands shown there (same as this guide)
  • The bind line sets USER_ID=<your CyberLS user id> and your real contact EMAIL (mapping uses USER_ID; the satellite never stores ownnodes:… as the node email)
  • Run bootstrap/start, then click Refresh nodes until you reach 10
# Example bind line (values come from CyberLs UI — copy from there)
cp -n .env.sample .env
sed -i 's|^USER_ID=.*|USER_ID=<FROM_UI>|' .env
sudo bash bootstrap.sh
sudo bash start-node.sh

Troubleshooting

Common checks

  • Docker missing → run install_docker.sh or full bootstrap.sh
  • Identity still running → wait; do not start the node yet
  • Container name conflict → stop-node.sh then start-node.sh
  • Need a clean slate → only if you intend to wipe local node data
